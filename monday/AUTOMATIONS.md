   - אין בו הקצאת אחראי מעמודה אחרת, למשל מנהל הפרויקט של הפרויקט המקושר.

   האפיון עצמו מציין את זה ב-§8.1.5.
2. **35 אוטומציות ידניות** הן 35 נקודות כשל בלי רישום. ב-Make כל ריצה נרשמת ביומן ונבדקת ב-M16.

## 4. אוטומציות מובנות להגדרה ידנית (כ-12)

ל-monday אין API ליצירת אוטומציות, ולכן את אלה צריך להגדיר בממשק.
**איך:**
1. פותחים את הלוח.
2. לוחצים "אוטומציות" (Automate) למעלה.
3. בוחרים "צור אוטומציה" (Create automation).
4. בונים את המשפט. השמות כאן הם השמות המדויקים של העמודות והתוויות.

### 4.1 A04, שינוי שבוצע ללא אישור (לוח "שינויים וחריגים")
> כאשר **בוצע** משתנה ל**מסומן** ← ואם **סטטוס** הוא **הוגש** ← שנה **סטטוס** ל**בוצע ללא אישור**, וגם הודע ל**[סמנכ"ל]**: "שינוי בוצע ללא אישור: {שם הפריט}"

בבונה אין "אינו", ולכן משכפלים את האוטומציה גם לתוויות **פוטנציאלי**, **בתמחור** ו**נדחה**, ארבעה עותקים בסך הכול.
M09a קולט את המעבר ל"בוצע ללא אישור" ומעדכן מיד את "שינויים ללא אישור" בתיק הפרויקט.

### 4.2 A13, משימה הושלמה (לוח "משימות ותפעול שוטף"; אפשר לשכפל גם ל"משימות רגישות")
> כאשר **סטטוס** משתנה ל**הושלם** ← הודע ל**מבקש**: "המשימה {שם הפריט} הושלמה", וגם העבר פריט לקבוצה **הושלם**

### 4.3 A16, תזכורת מעקב (לוח "משימות ותפעול שוטף")
> כאשר מגיע **תאריך מעקב** (ב-08:00) ← ואם **סטטוס** הוא **ממתין לגורם חיצוני** ← הודע ל**אחראי**: "מעקב היום: {שם הפריט}, ממתין ל-{ממתין ל...}"

### 4.4 A20, טפסי שטח (WorkForms)
יוצרים טופס מהלוח: "+ הוסף תצוגה" ← "טופס".

| לוח | שדות בטופס | אוטומציה |
|---|---|---|
| יומני עבודה | פרויקט, תאריך, מזג אוויר, עבודות שבוצעו, אירועים/עיכובים, תמונות, מגיש | אין צורך. M11b בודק חוסר |
| ליקויים ומסירה | פרויקט, מיקום, חומרה, קבלן אחראי, אחראי, תאריך יעד, תמונה לפני | כאשר נוצר פריט ← הודע ל**אחראי** |
| בטיחות | פרויקט, סוג, תאריך, חומרה, מועד סגירה נדרש, תמונות | כאשר נוצר פריט ← ואם **סוג** הוא **אירוע/כמעט אירוע** ← הודע ל**[סמנכ"ל]** |

### 4.5 A21, בקשה למשרד (לוח "משימות ותפעול שוטף")
1. **טופס** עם השדות: שם הבקשה, תחום, תאריך יעד, מבקש. אפשר להגדיר שהטופס ייצור פריטים בקבוצה **השבוע**.
2. **דוא"ל ללוח:** תפריט הלוח (⋯) ← "דוא"ל ללוח" ← העתקת הכתובת. הכתובת כוללת את מפתח ה-API של היוצר, ולכן משתפים אותה רק עם גורמים מהימנים (§7.1).
3. **אוטומציה:**
   > כאשר נוצר פריט ← הקצה את **[מנהלת המשרד]** ל**אחראי**, וגם שנה **סוג** ל**בקשה מהצוות**

### 4.6 A23, תבניות תת-פריטים (לוח "משימות ותפעול שוטף")
יוצרים אוטומציה אחת לכל ערך של **תבנית**. בכל אוטומציה מוסיפים פעולת "צור תת-פריט" אחת לכל שורה:
- **קליטת עובד:** חוזה העסקה · טופס 101 · ציוד · הרשאות monday ו-Google · הדרכת בטיחות · תדריך
- **פתיחת שנה:** חידוש מספור · ארכוב לוחות כבדים · עדכון מע"מ ותעריפים · חידוש ביטוחים
- **סגירת פרויקט:** מסירה · תיק מסירה · השבת ערבויות · דירוג קבלנים · סקר שביעות רצון · ארכוב
> כאשר **תבנית** משתנה ל**קליטת עובד** ← צור תת-פריט "חוזה העסקה", וגם צור תת-פריט "טופס 101", וגם …

### 4.7 שינוי פרטי בנק (לוח "ספקים וקבלני משנה")
> כאשר **פרטי בנק** משתנה ל**שונה** ← הודע ל**[סמנכ"ל]**: "פרטי בנק שונו: {שם הפריט}. לאמת טלפונית לפני תשלום", וגם שנה **אימות טלפוני חוזר** ל**לא בוצע**

### 4.8 הפסד (לוח "לידים והזדמנויות")
> כאשר **שלב עסקה** משתנה ל**הפסד** ← הודע ל**אחראי**: "נא לעדכן סיבת הפסד ומחיר מתחרה: {שם הפריט}"

(אין תנאי "ריק" בבונה, ולכן ההודעה נשלחת תמיד.)

### 4.9 העברה לקבוצות (רשות, לנוחות)
> כאשר **סטטוס** משתנה ל-X ← העבר פריט לקבוצה Y

| לוח | מיפוי |
|---|---|
| הזמנות | טיוטה ← טיוטות · ממתין \* ← באישור · מאושר/נשלח לספק/סופק חלקית ← מאושרות · הושלם/בוטל ← סגורות |
| שינויים | אושר ← אושרו · חויב/נדחה ← נסגרו |
| ליקויים | בטיפול ← בתיקון · נסגר ← נסגרו |
| חשבונות ספקים | אושר (אישור תשלום) ← מוכן לתשלום |
| חשבונות חלקיים | הוגש למפקח ← אצל מפקח · הופק מסמך ← הופק · שולם ← נגבה |

כל העברה צורכת פעולה אחת ממכסת האוטומציה של monday (25,000 בחודש).

**נתיב שגיאה:** תת-תרחיש (M17 דרך CallSubscenario) אי אפשר ליצור דרך ה-API של Make (מחזיר 500). לכן הלוגיקה של M17 משוכפלת בכל נתיב שגיאה:
1. רישום פריט "נכשל" ביומן.
2. הודעה לסמנכ"ל.
3. Break עם 3 ניסיונות חוזרים.

ההתנהגות זהה, אבל שינוי בטיפול בשגיאות מחייב חילול מחדש של כל התרחישים (`node make/scenarios.mjs <code>`).

## 7. מתג עצירה וחלופה ידנית (§8.7.8)

1. **עצירה:** ב-Make ← תיקייה ← מתג ההפעלה של התרחיש. אירועי webhook שמגיעים בזמן שהתרחיש כבוי נשמרים בתור (עד 667) ומעובדים כשמפעילים אותו מחדש.
2. **חלופה:**

   | תרחיש | חלופה ידנית |
   |---|---|
   | M03 | המאשר נקבע לפי טבלת §9 ומסמן ידנית. אפשר גם להפעיל את A02: "כאשר סטטוס משתנה ל'הוגש לאישור' ← ואם דרג אישור הוא X ← שנה מסלול אישור ל'ממתין X'" |
   | M09a | הרצה ידנית של M09b, שמראה את הפערים |
   | M07 | מיון לוח הספקים לפי "ימים לתוקף הקרוב" |
   | M08 | תצוגת "באיחור" לפי "ימי איחור" |
   | A12 | תצוגת "תוקף בתוך 90 יום" בחידושים, וסינון "ממתין להחלטה" במשימות |
3. **הרצה חוזרת אחרי תיקון:** "Run once". המפתחות מונעים כפילות.
4. **הרצה שנכשלה ונשארה בתור הניסיונות החוזרים** (DLQ, "Incomplete executions"): מוחקים אותה בממשק Make. אין לזה API. היום יש אחת כזו ב-M09a, מבדיקה שקדמה לתיקון.
